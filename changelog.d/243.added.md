LLM request lifecycle: answers are cached per payload, model and prompt in the scan state (a repeated scan sends nothing for unchanged code), `llm.budget` limits stop further requests, transient failures (429, 5xx, timeouts) are retried with backoff honouring `Retry-After`, and fenced JSON answers and refusal envelopes are normalised for every wire format.
An answer that does not parse is asked again up to `llm.max_repair_attempts` times (default 1); refusals are recorded as `llm_refused` and never retried. Concurrent reviews reserve their request before sending, so `llm.budget.max_requests` is never overshot. The scan summary shows LLM requests, cache hits, tokens and cost, and a pre-flight estimate is logged before the review.
