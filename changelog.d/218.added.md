The egress guard decides whether a request may leave: `EgressGuard.evaluate` checks the provider, its host, the privacy level, operator consent and that the body really holds the claimed payload, then runs every registered leak scanner over the final request bytes and returns a single-use ticket bound to that payload, provider and level, or a block code from a closed vocabulary. Any failure blocks the request, and so does a guard with no scanners. The new `[privacy.egress]` section bounds the guard; it is restricted, none of its keys switches a check off, and `provider_host_allowlist` is default-deny, so a remote provider needs a `base_url` on the list.
