The KavachBank sample application (`fixtures/kavachbank`) with a ground-truth manifest, and the first deterministic candidate pass over it. The application is deliberately vulnerable, uses synthetic credentials only and has recognisable banking logic (tiered interest with a festival bonus, a fee schedule with waivers, loan eligibility scoring, fraud thresholds by channel) across a Python API and a Node web service, with one planted weakness and one safe counterpart per class. The new `analyse-rules` stage runs nine native matchers (SQL injection, command injection, path traversal, SSRF, insecure deserialisation, weak password hash and static IV, missing authorisation, insecure direct object reference, reflected XSS) for Python and JavaScript over one traversal per file, and the new `aggregate` stage deduplicates by fingerprint and orders candidates by path, line and rule. `tools/gen_terms.py` generates the demo terms file from the manifest, with a pre-commit drift check.
