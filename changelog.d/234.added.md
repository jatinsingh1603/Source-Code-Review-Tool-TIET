Taint analysis stage: `analyse-taint` follows data from catalogue sources to catalogue sinks inside one function and publishes one `codekavach-taint` candidate per flow, with a `TaintPath` in execution order (`taint.http_param.sql` and similar rule ids, CWE and severity from the sink class). String building (concatenation, f-strings, `format`, `%`, `join`, template literals, `replace`) carries taint, a conversion to a number clears it for `sql` and `shell` sinks but not for `path` or `url`, and a sanitiser clears only the contexts its catalogue entry covers: one that covers the wrong context stays in the path as an inadequate-sanitiser step. A call the engine does not model gives an uncertain flow (`taint.uncertain`), branch guards are recorded (`taint.guards`), paths are capped by `taint.max_path_steps` and `taint.max_paths_per_sink` (shortest kept), and `taint.explain = true` writes a per-function JSON and Graphviz dump under the scan state directory only. New `[taint]` keys: `max_path_steps` (64), `max_paths_per_sink` (10), `loop_iterations` (3). A function that fails or runs out of time is reported as `taint_error` or `taint_timeout` and the rest of the file is still analysed. `engines.native.taint = false` turns the stage into a no-op.
