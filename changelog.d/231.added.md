Native rule matcher: rules written in the DSL now match Python and JavaScript code through `analyse-rules`, with `$X` and `$...X` captures, `_` and `...`, consistency of repeated captures, `any`/`all`/`none`, `pattern_inside`/`pattern_not_inside`, `ref`, the `where` constraints (`kind`, `is_constant`, `regex`, `min_length`, `equals`, `one_of`, `catalogue`) and taint delegation with a `rule.taint = unavailable` fallback. Candidates carry `engine="codekavach-rules"` and the pack id and version; a rule that raises or runs out of time is a `rule_error` or `rule_timeout` item failure and the other rules still run. Per-file results are memoised (file hash, grammar version, pack checksums, matcher version). `codekavach rules test` checks rules against annotated fixtures. `rules validate` now also reports unparseable patterns (`CK-RULE-011`) and `ref` cycles (`CK-RULE-015`). The thin-slice code matchers still run beside the rule packs until the shipped packs of E16-03 reproduce their findings.
