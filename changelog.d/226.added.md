`codekavach.analysis.engines.sarif` turns an engine's SARIF 2.1.0 log into `Candidate` objects. `ingest_sarif` and `ingest_engine_run` resolve every URI against the read-only scan view (`file://`, percent-encoding, backslashes, `uriBaseId`, `artifacts[]` indexes; anything that leaves the root is dropped and counted in one log event), convert 1-based SARIF regions to code-point columns, extract CWE in four ordered ways (properties, tags, taxonomies, a fallback table) and record which one fired, normalise severity and confidence from a per-engine table, compute the `ckfp1` fingerprint from the real file lines, and build a taint path from a code flow (sink-first engines are reversed, over-long flows trimmed by importance). `region.snippet` is not read, engine partial fingerprints are kept only as properties, and a malformed log raises instead of returning an empty list; `validate_log` lists the structural problems. The conformance kit in `tests/support/engines.py` replays recorded engine output through any adapter, and `--engines-live` re-records a case when the engine is installed (refused in CI). The data tables are TOML, not YAML, so no YAML parser becomes a runtime dependency.
