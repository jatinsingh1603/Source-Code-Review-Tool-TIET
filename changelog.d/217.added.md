Disclosure measurement and the metered needs-context loop. `privacy.slicing.metrics` measures every slice (lines, estimated tokens, functions, files, the fraction of its files and of the repository, stubs, truncation) and `ScanDisclosure` accumulates a scan: distinct files and functions, the union of disclosed lines per file (two overlapping slices count once, so the repository fraction is the share of lines prepared, never a sum), the distinct pairs of functions that appeared together as a call-edge count, and context expansions per candidate; `as_attestation_rows()` gives the rows for the report, with no path or name. `ContextResolver.resolve(request, vault=..., budget=...)` turns a model's request for one more definition into a `CodeSlice`: pseudonyms are mapped back through the restore engine, the definition is located, and the request is refused, with a reason kept locally and never sent, when the pseudonym is unknown, the definition is missing, ambiguous, excluded or vendored, the round cap is reached, the aggregation budget is used up, the request names too many symbols, or the link mode is `per_request`. New setting `privacy.slice.max_needs_context_rounds` (default 2, 0 turns the loop off). `Pseudonymiser.apply` and `process` take an optional scan-level generator so a symbol keeps its token across slices and rounds.
