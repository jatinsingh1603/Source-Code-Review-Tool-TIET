Default rule pack and catalogues: `rules/mit/` now ships catalogues for the Python standard library, Flask, Django, FastAPI, Node, Express and Koa (sources, sinks and sanitisers with the contexts they cover), and a `default` pack 1.0.0 of 74 rules for Python, JavaScript, C and C++ covering injection, cross-site scripting, path traversal and uploads, request forgery and redirects, deserialisation and XML entities, cryptography misuse, session and authentication, authorisation hotspots (`kind: hotspot`), mass assignment, races, logging, debug configuration and C memory-safety API misuse. Every rule has positive and negative fixtures, CWE, OWASP and remediation metadata. Symbols are matched through import resolution (aliases, from-imports, `require`), an unresolved receiver gives a partial match with lower confidence, and a sanitiser that does not cover the sink's context is reported with `sanitiser.inadequate`. New rule features: `inadequate_for`, the `parameter`, `request_derived`, `dynamic_string` and `constant_binding` kinds, `function_regex` on a clause, wildcard catalogue ids (`python.sink.shell.*`), and regex constraints that look through one local assignment. `public_names(catalogues)` lists the symbols the pseudonymiser's allow-list keeps in clear. `docs/reference/rule-coverage.md` (generated by `python -m codekavach.analysis.rules.coverage`) states which OWASP Top 10 categories and CWE Top 25 entries each language covers.
