A new built-in `parse` stage turns the discovered files into three artefacts: `symbols` (one scope-aware table per Python, JavaScript or TypeScript file, now with each import classified as `internal`, `stdlib` or `third_party`), `callgraph` (a best-effort, name-based graph between qualified functions that resolves calls across files through imports, marks callees it cannot resolve with a `?` prefix, and is documented as not sound), and `ast` (kept in memory only and parsed on demand). Import origin is decided from the project tree, `tsconfig.json`/`jsconfig.json` `paths` and `baseUrl`, `package.json` `imports`, and bundled, versioned standard-library lists; the environment is never consulted, so results are the same on every machine. Files that cannot be analysed (`too_large`, `parse_timeout`, `too_many_errors`, `unreadable`, `grammar_unavailable`) are listed in `symbols.skipped` and reported as item failures instead of stopping the scan, and results are cached per file so an unchanged file is not parsed again.
