`codekavach scan` now takes more than a directory. A zip, tar, tar.gz, tar.bz2 or tar.xz archive is extracted into a private working directory under the scan state, with limits on entry names, entry count, per-file and total size, compression ratio and depth, and no link is ever created. A git URL (`https`, `ssh`, `file` or `git@host:path`) is cloned with hooks, symlinks, submodules, LFS and the `ext::` transports switched off and the credential (`--git-credential`) passed through the environment, never the command line; `--ref` and `--depth` choose the revision. `-` reads one file from standard input (`--stdin-filename`). `--diff-since` limits the scan to files changed since a git ref or an earlier scan (`--include-deleted` also counts removed files), and `--subproject` limits it to detected sub-projects (`pyproject.toml`, `package.json`, `pom.xml`, `go.mod` and others). What a narrowing left out, and any submodule that was not scanned, is recorded in the new `ingest.coverage` artefact and warned about. The working directory is removed when the scan ends unless `--keep-state` is given.
