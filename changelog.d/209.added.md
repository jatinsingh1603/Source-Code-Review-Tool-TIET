The pseudonymiser: `Pseudonymiser.apply(slice, redaction, salt=..., level=..., scan_id=...)` turns a slice and the redaction of its layout into a validated `SanitisedPayload` and the `MappingBatch` for the vault, and `Pseudonymiser.process` also returns the provenance (allowlist, grammar and transformation versions, kept public names, conservative-classification and rename counts). The payload is laid out in a fixed order (a header naming only the level, a label per file, elision markers, then the stubs), classified, renamed through one plan, put back together with its fixed lines, checked to parse to the node-type sequence of its input (comments left out, an expanded shorthand compared as the pair it became, a new syntax error always a failure) and given a line map in which only slice lines map to file lines. A self-check refuses the payload if an original name of four characters or more survives, other than a public name or a shorthand key written beside its own token. Every failure is raised as `PseudonymError` with no text, and no path returns the original text. L1 uses the redacted text as it is, L2 and L3 take the full path, L4 raises `NotImplementedError` naming epic E27, and L0 raises `PseudonymError`. A public package named in an `import` or `require` string stays readable; a relative path is still pseudonymised.
