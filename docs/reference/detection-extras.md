# Optional detection layers

The native detectors (`secret.pattern`, `secret.assignment`, `secret.entropy`, the PII formats and
`term.domain`) run offline with no extra dependency and are all Demo 1 uses. This page describes
the layers that sit on top of them. Each is optional, each reports as absent when it is not
installed, and none is called by the native detectors.

## Absent extras

A missing extra is not an error. The capability is not available, the process logs one warning
per feature (`optional_extra_unavailable`, naming the extra to install), and detection continues
with the native detectors. The optional modules are not imported when
`codekavach.privacy.detect` is imported. A test imports the package in a clean interpreter and
checks this.

## External secret engines

`codekavach.privacy.detect.secrets.adapters` runs two scanners as subprocesses and reads their
JSON: a Go regex-and-entropy scanner (Gitleaks) and a Python baseline scanner (detect-secrets).
They are installed by the client and are not imported or shipped (see the licence manifest below).

An engine is third-party code running on a host that holds client source, so the invocation is
constrained, and a test asserts each point through a fake runner that captures the argument vector
and the environment:

| control | how |
|---|---|
| no repository access | the files to scan are copied into a private temporary tree (regular files only, no symlinks, a size cap), which is made read-only |
| no repository configuration | engine configuration files such as `.gitleaks.toml` and `.secrets.baseline` are not copied, so the engine reads none; inline suppression comments are switched off where the engine allows it |
| no live validation | detect-secrets runs with `--no-verify`; Gitleaks has no validation. Validation would send the candidate secret to its issuer |
| no network access requested | no proxy variable and no credential is passed, home and configuration directories are private, and the arguments name no remote resource |
| time and memory limits | 120 seconds of wall-clock time by default; `GOMEMLIMIT` for Go; an address-space limit on POSIX systems |
| output is data | JSON is parsed strictly; malformed output raises `AdapterError` and returns no partial list; error messages do not quote output |

Repository-supplied engine configuration is refused because it is attacker-controlled input to
the scanner: a configuration file in a scanned repository has led to remote code execution in a
linter (`docs/research/INSIGHTS.md` section 7), and a client's repository is not trusted to
configure a tool that runs on the scanner host.

Blocking sockets at the operating-system level belongs to the sandbox the engine runs in, not to
the adapter. The adapter tests run with the test suite's network block active.

Each engine's rule identifier maps to a subtype of the closed vocabulary through an explicit
table. A rule that is not in the table maps to `generic_credential` at `LOW` confidence and is
counted in `EngineScan.unmapped`; it is not dropped and does not create a subtype. Findings from
an engine are `MEDIUM`, so on a conflict the native `HIGH` detectors win, and the union is done by
`resolve_overlaps`.

## Name recogniser

`codekavach.privacy.detect.pii.ner.NerDetector` reports `person_name`, `organisation`, `location`
and `nric_or_national_id` spans from a locally installed spaCy pipeline (`en_core_web_sm` by
default). It is registered only when `privacy.pii_locales` enables a locale, and it reports
`MEDIUM` confidence. It does not download a model: with the library or the model absent it returns
no spans and logs one warning. `codekavach doctor` reports the model as `privacy:ner-model`, so an
air-gapped installation can find the gap at set-up and not at scan time. The extra is `pii`
(`codekavach[pii]`).

## Mining domain terms

`codekavach privacy terms suggest [TARGET] [--scan ID] [--limit N]` mines the vocabulary of a
stored scan and writes candidate terms to a file in the state directory, in the format of a terms
file, with the score above each term. The score of a sub-word is
`log(repository_rate / baseline_rate)`: a word that is rare in general code and frequent in the
repository (for example `accrual`) scores high, a common word (`value`) scores near zero. Keywords,
builtins, the public allowlist and the terms already configured are excluded. The baseline is the
table `privacy/detect/data/term_baseline.tsv`, generated by `tools/gen_term_baseline.py` from the
CPython standard library; its header records the source and licence.

The command is a suggestion path. Nothing is redacted from a suggested term until a person copies
it into `privacy.domain_terms`. The list is a summary of the client's vocabulary, so it is written
to the private state directory and not to the project, the terminal shows a bounded sample, and the
JSON output carries counts and the file path but no word.

## Licence manifest

`privacy/detect/data/optional_engines.toml` declares, for every optional engine, library, model,
bundled data file and evaluation dataset, an SPDX identifier, a distribution mode (`bundled`,
`client-installed` or `evaluation-only`) and a hosted-use flag, following the standing policy in
`docs/research/INSIGHTS.md` section 6.2. A test checks that every adapter and the default model
have an entry and that a bundled item has a licence the project allows.

## Measuring the detectors

`tools/detector_eval.py` scores the detectors against labelled corpora; the measured values are in
`docs/research/DETECTOR_EVAL.md`.
